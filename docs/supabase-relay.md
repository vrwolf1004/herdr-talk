# Supabase 릴레이

## 현재 상태

Supabase 릴레이는 **1대다 방** 모델이다. 서버가 방을 만들 때 무작위 8자리 방 ID를 만들고 만든 사람에게 돌려준다. 다른 사람은 그 방 ID를 입력해 같은 방에 참가한다.

**폐기됨: 상대 ID 기반 1:1 Supabase 릴레이.** 상대 쌍으로 채널을 만들거나 상대의 ID를 조회해 1:1로 연결하는 이전 방식은 지원하지 않는다.

## 방 사용

1. Supabase 모드에서 프로젝트 URL, publishable 키와 표시 이름을 입력한다.
2. **방 만들기**를 누른다. 서버가 만든 8자리 방 ID가 방 ID 칸에 들어간다.
3. 저장한 뒤 그 코드를 다른 참가자에게 전달한다.
4. 다른 참가자는 같은 값을 방 ID 칸에 입력하고 저장해 참가한다.

방 ID는 `A-Z0-9` 8자리다. 입력할 때 대소문자는 구별하지 않으며, 공백과 대시는 무시한다.

방은 생성 시점부터 **24시간** 사용할 수 있고 연장할 수 없다. 만료된 방에 참가하면 서버는 `410`을 반환한다. 만료 방 정리는 `pg_cron`으로 설계되어 있으며 `0005_room_expiry.sql` 주석에 기록되어 있다. 만료·정리 기능은 **구현됨, 미배포** 상태다.

## 식별 코드와 신뢰

- 방 ID는 8자리 `A-Z0-9` 코드다. 입력에서 대소문자를 구별하지 않고 공백과 대시를 무시한다.
- 레거시 상대 ID는 서명된 peer 행 게시용으로만 남고, 방 참가나 1:1 라우팅에는 쓰지 않는다.
- trust 코드도 8자리다. SAS 커밋 방식으로 바꾸는 설계는 확정됐지만 **구현 대기** 상태다.

## LAN과의 관계

`local` 모드는 LAN 전용이다. UDP 브로드캐스트로 상대를 찾고 보이는 **모든** 상대에게 메시지를 보낸다. 이는 1:1 기능이 아니라 다수 참가자 LAN 채팅이다.

`supabase` 모드는 방 기반 인터넷 릴레이다. LAN과 Supabase는 별도 전송 방식이며, 실제 전송·화면 동작의 세부 사항은 미확인인 부분을 추측하지 않는다.

## 배포 전 보안 과제

다음 문제는 아직 해결되지 않았으며 **배포 전 해결 필요**하다.

- 방 RLS가 전체 공개 상태다.
- 방 생성과 참가 요청에 서명 검증이 없다.

메시지 암호화, 채널 권한, 배포된 Edge Function의 실제 상태는 이 문서에서 확인하지 않았다.
